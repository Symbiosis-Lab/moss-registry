# PDF OCR

Reads one PDF and prints one JSON result; the deriver of a moss plugin that shows a folder's PDFs as web pages. Output is deterministic for the same bytes and the same binary.


Install: from moss's plugin catalog, or by unpacking the registry release's `pdf-ocr-<version>.zip` into a site's `.moss/plugins/pdf-ocr/`. Its manifest names this version's archive on the registry release by URL and sha256; moss downloads and unpacks it into `~/.moss/stacks/` the first time the site is built, after the user has allowed the plugin. There are three builds: macOS on Apple silicon (`darwin-arm64`) and Linux on x86-64 and ARM (`linux-x64`, `linux-arm64`, glibc 2.35 or newer). Each archive carries pdf-ocr, pdfium and Tesseract with its libraries and English language data, so no Tesseract needs to be installed, and the licences of all of them in `licenses/`.

Release: the registry builds and publishes it. On a merge to moss-registry's `main` with a new version in `Cargo.toml` and `../assets/manifest.json`, CI runs each `build-<platform>.sh` on a runner of that platform. On macOS, `build-darwin-arm64.sh` runs `scripts/build.sh`, then `python3 -I scripts/package-macos.py`, which relocates Homebrew's Tesseract into the archive, checks nothing still loads from Homebrew, and refuses a tesseract other than the version pinned in `vendor.toml` (unless `PDF_OCR_ALLOW_TESSERACT_MISMATCH=1`, for local use only). On Linux (Ubuntu 22.04 runners), `build-linux-<arch>.sh` runs `scripts/package-linux.sh`, which builds Tesseract and leptonica from the sources pinned in `vendor.toml` at the same versions, links them statically so the archive needs only glibc, and checks the result reports those versions. Every build ships the pinned, sha256-checked `eng.traineddata`. The pins keep the OCR fingerprint the same from build to build, so a new release reuses a site's cached readings unless it moves a pin. For a local build instead, `scripts/install-dev.sh <site>` points a site at `target/release/`.

Build: `scripts/build.sh` fetches the pinned pdfium (`vendor.toml`), builds, and places `libpdfium.dylib` beside `target/release/pdf-ocr`. Tests: `scripts/fetch-pdfium.sh && cargo test --release`. Fixtures are regenerated with `scripts/make-fixtures.py` (needs Pillow and pypdf).

Protocol: stdin `{"path": "/abs/file.pdf"}`; stdout one line, either `{"kind":"derived","fragments":{"text":...},"facts":{"title":...,"description":"<n> pages[, scanned|, partly scanned]","date":"YYYY-MM-DD"}}` or `{"kind":"skip","reason":...,"message":...}`; any other failure is a non-zero exit with a one-line reason on stderr. Pdfium is found next to the executable, else `PDF_OCR_PDFIUM`; tesseract next to the executable, else `PDF_OCR_TESSERACT`, else PATH, and its absence is a failure only when a page needs OCR.

Text: the text is plain paragraphs. Lists, headings and tables are not inferred; wrapped lines are joined into paragraphs, a running header or footer stays once (the header on the first page, the footer on the last, since it can carry a code, a classification or a date), page numbers are dropped, and everything extracted or OCR'd is backslash-escaped so it renders as the literal text (a `- - - -` leader rule, a leading `#` or `1.`, `*stars*`, `[brackets]`). A New York City civil service title specification (a header with `CODE NO.` or `TC` and a five-digit title code; the layout is described in [public-document-formats](https://github.com/Symbiosis-Lab/public-document-formats/tree/main/formats/nyc-dcas-title-specification)) takes its title fact from the lines above its "Duties and Responsibilities" heading and its `date` from the footer's month.day.year. Otherwise the title fact is the subject of the first page when a line opens with `Audit Status:`, `Re:` or `Subject:` (cut before `for Audit Period`, `Determination:` or the sentence end, at most about 100 characters); else the largest type on the first text page, skipping letterhead lines; else the PDF's metadata; else the file name. The `date` fact is the first full date on the first page (`June 9, 2020`, `06/09/2020`, `2020-06-09`), leaving out the dates of an audit period or any `X to Y` range, and is omitted when there is none.

Page markers: from page 2 on, each page start in the text is marked with a markdown link to that page of the source file, `[p. 3](report%202019.pdf#page=3)` (the base name, percent-encoded as one URL path segment). The marker opens the paragraph that starts the page, or sits inline, with a space on each side, where a paragraph runs across the page break (it is then one paragraph; a word hyphenated across the break is repaired). A page without text still gets its marker. When any page was read by OCR, the text begins with a `> [!note]` block saying so.

Across platforms: every build has the same pdfium release, Tesseract and leptonica versions and language data, and renders a page to byte-identical pixels. Tesseract's float arithmetic is compiled by Apple clang on macOS and by gcc on Linux, though, so OCR can rarely differ by a character. On the eleven scanned title specifications in [public-document-formats](https://github.com/Symbiosis-Lab/public-document-formats/tree/main/formats/nyc-dcas-title-specification), 10 texts are byte-identical between darwin-arm64 and linux-arm64; in 82989 one token of scan noise after the footer date reads `“he` on macOS and `"bh` on Linux. Text-layer pages are not affected.

Cache: reading a PDF (its text layer, or OCR where a page has none) is the slow part, so what was read is cached per PDF and the text is shaped from it on every run. The key is the SHA-256 of the PDF plus the pdfium library, the Tesseract version, language data and settings, and `EXTRACT_FORMAT_VERSION` in `src/cache.rs`; shaping changes never invalidate it. Entries live in `$MOSS_CACHE_DIR/extract` (the cache directory moss gives a plugin, which its sandbox lets this binary write), else `$PDF_OCR_CACHE`, else `~/Library/Caches/pdf-ocr/extract` (macOS) or `$XDG_CACHE_HOME/pdf-ocr/extract` / `~/.cache/pdf-ocr/extract`, are written atomically, and the least recently used are deleted past 2 GB. A missing, unwritable or corrupt cache only means the PDF is read again.
